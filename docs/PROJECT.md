# Замысел и границы первой версии

## Идея

Есть одно общее двумерное поле. Участник может добавить ограниченное число вершин и провести связи между ними. Все видят один и тот же граф. Это отправная точка; поведение можно менять по мере обучения.

## Предварительные правила MVP

- Вершина имеет идентификатор и координаты на поле.
- Ребро соединяет две существующие разные вершины. Повторяющиеся связи между той же парой не допускаются.
- Сервер проверяет координаты, наличие вершин и лимит создания. Проверка только в браузере недостаточна.
- Для первого локального прототипа можно начать без учётных записей. Перед публичным запуском нужно определить, как распознавать участника и защищать лимит от обхода.
- Удаление, перемещение, цвет, подписи и сложные правила связей пока вне первой версии.

Число вершин на участника, размер поля, правила владения связями и способ идентификации ещё не утверждены. Их стоит определить перед реализацией ограничений.

## Начальный технический путь

- **C# и .NET 10**: установлен SDK 10.0.100; .NET 10 — поддерживаемый выпуск LTS.
- **ASP.NET Core Minimal API**: небольшое HTTP API позволяет сначала разобраться с запросами, ответами и проверкой входных данных.
- **Хранение**: сначала в памяти процесса, чтобы понять модель и API; затем SQLite через EF Core для сохранения между запусками.
- **Обновления в реальном времени**: после работающего HTTP API рассмотреть SignalR. До этого клиент может перечитывать граф вручную или по таймеру.
- **Интерфейс**: простой браузерный клиент после базового API. Выбор фреймворка пока не требуется.

Это учебная последовательность, а не обязательная архитектура конечного сервиса.
